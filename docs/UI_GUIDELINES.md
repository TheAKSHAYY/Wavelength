# UI Guidelines

## Design Intent

The interface is built to feel like a focused creator dashboard rather than a generic SaaS app. It emphasizes clarity, speed, and actionability.

## Core Visual Principles

### 1. Utility first

The product should help users make quick decisions, not distract them with decorative complexity.

### 2. High signal density

The dashboard should present information in compact blocks, cards, and summary sections.

### 3. Action-oriented summaries

Each panel should show outcomes and next actions quickly, even if the underlying output is AI-generated.

### 4. Trust but verify

AI-generated content should look clear and useful, but not appear as final authority. The UI should allow fast editing or reinterpretation.

## Layout Philosophy

The dashboard uses a modular panel layout with sections such as:

- overview metrics
- trend and insight cards
- recommendation panels
- generation panels
- roadmap or schedule views
- content packages

Panels should be compact and readable, with generous spacing and direct headings.

## Visual Hierarchy

Use the following order of emphasis:

1. page title and major section headings
2. key metric cards or status signals
3. actionable CTA buttons
4. supporting text and references
5. raw or generated details in lower-importance groups

## Component Style Guidelines

### Cards

- keep them consistent in border radius and spacing
- use toned backgrounds or subtle contrast for separation
- keep text scannable and concise

### Metrics

- use labeled metrics with positive/neutral/negative emphasis where needed
- keep units and labels obvious
- apply color sparingly to reduce noise

### Buttons

- use clear action labels
- differentiate primary and secondary actions visually
- maintain consistent alignment across sections

### Inputs

- provide a visible placeholder or label
- keep entry flow simple and compact
- maintain accessible contrast ratios

## Content Style

- prefer practical, creator-friendly language
- keep headlines direct and outcome-focused
- use bullet lists for outputs and recommendations
- reduce long paragraphs in panel summaries

## Accessibility

- ensure sufficient contrast between background and text
- use semantic headings and labels
- support keyboard navigation for interactive controls
- avoid color-only meaning for critical states

## Responsive Behavior

The project is primarily a local dashboard, but layout should remain readable across different screen widths.

Best practice:

- stack panels naturally on narrower screens
- keep aggregated summary cards intact
- maintain readability without excessive wrapping

## Future UI Improvements

Recommended enhancements:

- collapsible side panels
- mobile-first adjustments
- inline editing for generated suggestions
- saved project states
- richer visual trend graphs and comparison charts
